HAL 与 FreeRTOS 共用 SysTick

SysTick
每 1ms 中断
→
HAL_IncTick()
维护 HAL 毫秒计数
+
xPortSysTickHandler()
调度器启动后维护 RTOS Tick
void SysTick_Handler(void) { HAL_IncTick(); if (xTaskGetSchedulerState() != taskSCHEDULER_NOT_STARTED) { xPortSysTickHandler(); } }

为什么启动前不会卡住

HAL_IncTick() 一直存在，因此初始化阶段的 HAL_GetTick() 和 HAL_Delay() 仍然有时间推进。

为什么没有重复定义

没有把 xPortSysTickHandler 宏改名成 SysTick_Handler； it.c 中只保留唯一入口并显式调用它。

任务中优先使用 vTaskDelay()。不要在关闭中断或 FreeRTOS 临界区内调用 HAL_Delay()，因为此时 SysTick 中断无法执行。

已经解决的问题

A1586E Bad operand types

原因：汇编指令读到了带移位的宏表达式。

处理：syscall 优先级改为字面量 80，内核优先级改为字面量 240。

L6200E SysTick multiply defined

原因：宏改名与 it.c 的同名函数同时存在。

处理：取消 SysTick 宏改名，由 it.c 包装调用。

CubeMX Generate 后检查

  • SVC_Handler 没有被重新生成；若出现则继续注释。
  • PendSV_Handler 没有被重新生成；若出现则继续注释。
  • SysTick_Handler 同时保留 HAL tick 和调度器状态判断。
  • FreeRTOS.h、task.h 和 extern 声明仍在 USER CODE 区。
  • SysTick 直接改名宏仍处于注释状态。
  • Keil 中 RTOS 源文件、Include Paths、ARM_CM4F 和 FPU 设置仍正确。
