这是什么队列

一块 128 字节数组，外加两个下标：

  • head：下一个空位，只由中断 RxPush 写。
  • tail：下一个未读字节，只由 main 里 ReadByte 写。

绕圈用 (下标 + 1) % 128。写到 127 的下一格是 0。

单生产者、单消费者；满了丢新字节；留一格区分空和满。这是初等写法，给现在的回显用。

空和满

空

看现在的两个下标：head == tail。

读写停在同一格，没有未读数据。

满

先算 next = (head + 1) % 128，再和现在的 tail 比。

next == tail 就是满。再写会盖掉还没读走的。

(head + 1) % 128 和 (tail + 1) % 128 结果相同，只是空的连带现象。代码里直接比 head == tail。

满了：不写缓冲，head 不改成 next，仍是原来的数。next 是局部变量，return 后就没了。

128 格最多存 127 字节。不留一格的话，满和空都会变成 head == tail。

两个函数

RxPush：中断往里放

next = (head + 1) % 128; if (next == tail) return; /* 满，丢这一字节，head 不动 */ buf[head] = data; head = next;

ReadByte：main 往外拿

if (data == 0) return 0; if (head == tail) return 0; /* 空 */ *data = buf[tail]; tail = (tail + 1) % 128; return 1;

main 里有货才回发：

if (USART6_LL_ReadByte(&ch)) { USART6_LL_SendByte(ch); }

为什么能收超过 128 字节

128 是同时最多暂存 127 字节，不是一辈子只能收 128。

中断推进 head，main 取走后 tail 跟上，同一格会写很多次。边收边回显时，缓冲里往往只有几字节，一次贴几百字节也能原样回来。

来得比取走快、未读顶到 127 时，RxPush 才丢新字节。

中断可以打断 main，但不会把 main 停死

RXNE 来了就插入 ISR：读 DR、入队、马上返回。main 从刚才那条指令接着跑，再 ReadByte、等 TXE 回发。

不要在 ISR 里 while (!TXE) 发送，不要在 ISR 里 printf。

NVIC 优先级 5，对齐 configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY。当前 ISR 不调 FreeRTOS API。

ORE 必须先读 DR 再 return，否则 RXNEIE 会让中断一直进。不要再调用 LL_USART_ClearFlag_ORE()，它会多读一次 DR。

不是终极版

现在以后按需再换
% 绕圈，留一格2 的幂用 & 127；或加计数放满 128
满了丢新字节要最新数据时改丢最旧的
逐字节中断DMA + IDLE 收整包
main 空转读FreeRTOS 队列 / StreamBuffer

DMA 还没做。调度器还没启动，回显仍在 main 循环。USB 仍软断开。
