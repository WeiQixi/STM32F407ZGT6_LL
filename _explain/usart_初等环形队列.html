256 格单生产者 / 单消费者队列

接收中断：生产者

head 指向下一个空位，只由 RxPush 推进。

队列满时丢弃新字节，不覆盖尚未读取的数据。

接收任务：消费者

tail 指向下一个未读字节，只由任务推进。

Peek 只查看；确认后由 Drop 消费。

空：head == tail。满：((head + 1) & MASK) == tail。

256 格故意留一格，因此最多同时积压 255 字节。任务取走数据后，格子可以反复使用。

USART6_RX_BUF_SIZE = 256 USART6_RX_MASK = 255 (254 + 1) & 255 = 255 (255 + 1) & 255 = 0 /* 回到队头 */

按位与代替取模的前提是队列容量必须为 2 的幂；头文件使用编译检查保证这一点。

数据包格式

AASOF0
55SOF1
LENDATA 长度
DATA0～64 字节
XOR异或校验
  • LEN 不包含包头、LEN 自身和 XOR。
  • XOR = LEN ^ DATA[0] ^ ... ^ DATA[LEN-1]，不包含包头。
  • 最大完整帧：2 + 1 + 64 + 1 = 68 字节。

载荷 “Hi”

DATA = 48 69 LEN = 02 XOR = 02 ^ 48 ^ 69 = 23 帧 = AA 55 02 48 69 23

解包与重新同步

  1. 包头不足：保留已有字节，等待接收中断继续入队。
  2. 包头不匹配：丢 1 字节，继续寻找 AA 55。
  3. LEN 超出 0～64：丢 1 字节，继续寻找包头。
  4. 数据未收完整：保留半包，最多等待 20ms。
  5. 半包超时或 XOR 错误：丢 1 字节并重新同步。
  6. 校验通过：复制 DATA、消费完整帧并返回成功。

粘包

第一帧按 LEN 消费后，第二帧仍留在队列中，任务下一轮继续解析。

载荷包含包头

当前 LEN 合法时按长度取完整载荷，不会把 DATA 中的 AA 55 误当新帧。

重复包头

AA 55 AA 55... 的第一个 LEN 是 170，超过上限，只丢一个字节后继续查找。

前置噪声

11 22 33 会逐字节丢弃，直到找到真正的 AA 55。

中断与任务分工

执行位置只负责什么禁止什么
USART6 ISR 读 DR、字节入队、立即返回；ORE 先读 DR 等待 TXE、printf、解包、发送数据
USART6_PktTask 调用 ReadPacket；成功后调用 SendPacket 回发 同时调用 ReadByte 抢同一个 tail
main 初始化、创建任务、启动调度器 继续执行旧的逐字节回显循环

没有完整数据包时，测试任务调用 vTaskDelay(1) 让出 CPU。

SendPacket 会轮询等待 TXE/TC，只能在任务或普通线程中调用。

当前边界

  • 接收仍是逐字节 RXNE 中断，DMA + IDLE 尚未实现。
  • 队列满时丢新字节，当前没有溢出计数。
  • XOR 是轻量校验，不是强校验；正式协议可改用 CRC16。
  • 发送仍为轮询方式，当前发送任务会等待，但高优先级任务仍可抢占。
  • USB 仍然软断开，不要连接主机测试枚举。
