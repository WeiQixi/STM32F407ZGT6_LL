3. 真正有事的是 uart5_temp_buf，不是 str

上次按行原文（你说下面都没看懂）
L184：uart5_temp_buf 是这个 if 的栈数组。 L191：从 DMA 环形缓冲拷到栈。 L197：把栈地址交给 DMA。 L199：} 结束，uart5_temp_buf 生命周期结束。 L197 的 DMA 通常还没搬完。下一次进循环、或 L208 再开一个 256 字节栈数组，会盖掉这块。USART6 发出去的是已经释放的栈。 L208–211：和 L184–197 相同。
这次对应在讲什么
DMA 发送不拷贝内容，只记下指针，硬件过一会儿自己来读。
str 现在碰巧没事，只因为任务没退出。
uart5_temp_buf 在 if { } 里。这块要失效之前，必须先让 DMA 停：等 Tx 完成，或 Abort/关掉 DMA。 现在 L199 的 } 直接出去了，DMA 还开着，等于拆掉正在读的内存。

同一条栈，两个时刻

时刻 1：还在 if 里面（L197 刚调用）
uart5_temp_buf = "ABC..." 还在
DMA 正在（或即将）从这里读

指针有效。这一瞬间是对的。

时刻 2：L199 的 } 已经执行
uart5_temp_buf 已经死了
DMA 还在读同一个地址

错在这里：缓冲已经死了，DMA 没关。正确顺序是先等发完或 Abort，再出 }。

规则就一句：DMA 还开着，源地址就不能先失效。任务退出、花括号结束，都算失效。要结束这块内存，先关上 DMA。

4. 环形缓冲跨边界，连续 memcpy 会拷错

上次按行原文
L142：指针指向 uart5_rx_buf[start]。这只是一段连续地址，绕回 0 时后半段不在这后面。 L191 的第二个问题：memcpy 假定 [rx_data_ptr, rx_data_ptr+rx_len) 连续。 环形缓冲：start=250，len=20 → 合法数据是 buf[250..255] 再加 buf[0..13]。 memcpy 从 &buf[250] 连拷 20 字节，会读到 buf[256] 以外，后 14 字节永远拷不到。 uart5_read_pos / usart6_read_pos 声明了没用。
这次对应在讲什么
DMA 环形缓冲是转盘：写到末尾接着从 0 写。
一包数据可能拆成两截：尾巴 + 开头。
memcpy 只认「从某地址往后连着拷」，不会自己绕回 0。

5. 忙就丢包；一个 flag，来不及读就被盖

上次按行原文
L97–100：忙就返回，uart_task 不看返回值。L197、L211 失败时这包数据没了。 L215：最多 10ms 才看一次 rx_flag。IDLE 一包一个 flag（it.c L254），第二包进来会把第一包的 rx_len 盖掉。10ms 内来两包，第一包直接丢。 L253–254：只有一组 len/flag。任务没取走时下一包 IDLE 直接覆盖。没有队列。
这次对应在讲什么
两件独立的「丢包」，别混在一起。
发送丢：USART6 上一包 DMA 没发完，UART_DMA_Send 看到 flag=0 就返回 HAL_BUSY。任务当成功了，这包不再发。
接收丢：ISR 只有一个 rx_flag + 一个 rx_len。第二包 IDLE 进来，第一包的长度被覆盖。任务 10ms 转一圈，中间来两包只能看到最后一包。

发送：忙就丢

1. 任务把包 A 交给 USART6 DMA，flag 置 0（忙）

2. 马上又想发包 B，if (*flag_ptr == 0) return HAL_BUSY;

3. 任务不检查返回值 → 包 B 没了

if (*flag_ptr == 0) return HAL_BUSY; UART_DMA_Send(...); // 返回值扔掉了

接收：一个格子记一包

墙上只有一块牌子，写着「当前这一包多长」。

包 1 到：牌子写 10。任务还在 Delay(10ms)。

包 2 到：牌子改成 30。包 1 的 10 被擦掉。

任务醒来只看到 30，包 1 没了。

6. UART5 和 USART6 空闲中断不是同一套

上次按行原文
UART5 L250：> 不是 >=。current_pos == last_pos 时走 else，len 被算成整圈 256。空闲中断、DMA 没动时就会假的 256 字节包。 USART6 L307：>=，相等时 len=0。这点和 UART5 相反。 USART6 L305：多了 % SIZE。刚好写满一圈时 UART5 得到 current_pos=256，USART6 得到 0。 USART6 L310–314：len==0 直接 return。USART 中断里 IDLE、TC、错误共用一个向量。return 后 HAL_UART_IRQHandler 不跑，TX 完成回调可能丢，错误位可能一直挂。
这次对应在讲什么
两个串口干同一件事（DMA 循环收 + IDLE 算一包有多长），代码却抄成两份，三处对不齐。
记三个差别：比较符、满圈取模、空包要不要 return。

UART5（it.c 约 L243）

current_pos = SIZE - remaining; // 满圈可以是 256 if (current_pos > last_pos) // 相等走 else len = current_pos - last_pos; else len = (SIZE - last_pos) + current_pos; // 相等时 = 256 假包 清 IDLE; HAL_UART_IRQHandler(); // 总会走到

USART6（it.c 约 L302）

current_pos = (SIZE - remaining) % SIZE; // 满圈变成 0 if (current_pos >= last_pos) // 相等 len=0 len = current_pos - last_pos; else len = current_pos + (SIZE - last_pos); if (len==0) { 清 IDLE; return; } // HAL 被跳过 HAL_UART_IRQHandler();
情况UART5USART6
DMA 没动，又进了一次 IDLE（位置没变） len=256，当成一整包 len=0，丢掉这帧（这点比 UART5 对）
len=0 时后面怎么办 继续进 HAL，TC/错误还能清 return，HAL 不跑，发送完成/错误可能漏
刚好写满 256 字节一圈 current_pos=256 current_pos=0（多了一次取模）

USART6 过滤空包是对的，但用 return 把 HAL 也跳过了，副作用比「过滤」大。UART5 不过滤空包，会造假的 256 字节。

7. 其余（上次放在「次要」里的）

上次按行原文
L112、L119：UART5 TX/RX 都是 GPIO_NOPULL。RX 浮空，空闲电平不稳，容易误触发 IDLE。 L183：USART6 是 GPIO_PULLUP，两边 RX 策略不一样。 L135 vs L199/L220：UART5 DMA 关 FIFO；USART6 TX/RX 开 FIFO。字节串口开 FIFO 有时会让 RX 多攒几个字节才进内存，IDLE 长度和「线上已经停」对不齐。 L84、L89：发送路径夹 LED。 L26–33：UART_SendByte 轮询 DR，和 DMA 是两套路径。
这次对应在讲什么
这些不是「拷错 20 字节」那种必现逻辑 bug，是两边配置不对称，排障时会干扰你。
RX 要上拉；两个串口应当同一套 DMA/GPIO 策略；LED 不该夹在发送函数里；轮询写 DR 不要和 DMA 混用。
