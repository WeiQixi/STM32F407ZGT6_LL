1. CPU 自己搬字节时，数据怎么走

接收路径

PC7 → USART6移位寄存器 → DR → RXNE中断 → CPU读取DR → 软件环形队列。

发送路径

CPU等待TXE → CPU写DR → USART6移位发送 → 最后等待TC。

不用 DMA 时，每收到一个字节，CPU 进一次中断，自己从 DR 把字节读走；要发送时，CPU 自己把字节写进 DR。线上的起始位、数据位、停止位仍由 USART 硬件产生。

2. RXNE中断接收

RXNE 表示接收寄存器里已经有一个字节，CPU 该来读了。USART6 收完一个字节、放进 DR 之后，RXNE 变成 1，CPU 进入 USART6_IRQHandler()。

  1. 初始化阶段配置USART6_IRQn优先级并在NVIC中启用该中断。
  2. 调用 LL_USART_EnableIT_RXNE(USART6)，允许RXNE事件提出中断请求。
  3. 硬件收到一个字节后置位RXNE，CPU进入中断入口。
  4. USART6_LL_IRQHandler()读取DR，读取动作同时清除RXNE。
  5. USART6_LL_RxPush()把字节追加到软件环形队列，任务随后读取。
if (LL_USART_IsActiveFlag_RXNE(USART6) && LL_USART_IsEnabledIT_RXNE(USART6)) { data = LL_USART_ReceiveData8(USART6); USART6_LL_RxPush(data); }
CPU工作量：每收到一个字节进入一次USART6中断。115200 8N1约每秒最多传输11520个字符，持续满速接收时也会产生相同数量级的中断。

变量含义修改者
usart6_rx_buf[]保存已由CPU从DR取出、尚待任务处理的字节中断写入，任务读取
usart6_rx_head下一次写入位置RxPush()

nexthead前进一步后的候选位置RxPush()局部变量
next = (head + 1) % BUFFER_SIZE; if (next == tail) { 队列已满，丢弃当前新字节; } else { buf[head] = data; head = next; }

数组空出一格，用来区分“空”和“满”。head == tail 是空；再写一个就会追上 tail，这时算满，新字节丢掉。工程里的数组是 256 格，最多留下 255 个字节。

ReadByte 是什么，现在有没有人调用

int USART6_LL_ReadByte(uint8_t *data){ uint16_t tail; if(data == 0) return 0; if(usart6_rx_head == usart6_rx_tail) return 0; tail = usart6_rx_tail; *data = usart6_rx_buf[tail]; usart6_rx_tail = (uint16_t)((tail + 1) & USART6_RX_MASK); return 1; }

它从软件队列取走 1 个字节。调用者要先准备一个 uint8_t 变量，把地址传进来。队列空，也就是 head 等于 tail，返回 0。否则把 tail 指着的那一格写进这个变量，tail 加 1，返回 1。

当前工程里只有这个函数的定义，main、回显任务和协议解析都没有调用它。回显任务调用 USART6_Packet_Read()，解析器用 RxPeek 查看字节，确认是一整帧之后再用 RxDrop 一次丢掉这一帧。ReadByte 和解析器共用同一个 tail，两边一起读会把对方的字节拿走。

4. TXE与TC轮询发送

标志置位条件发送函数的动作
TXE发送数据寄存器是空的。CPU 可以把下一个要发出去的字节写进 DR等到 TXE 为 1，再写这一字节
TC写进 DR 的字节已经从 PC6 移完，最后一个停止位也离开引脚一整段都写完后，再等 TC，然后函数才返回
void USART6_LL_SendByte(uint8_t data) { while (!LL_USART_IsActiveFlag_TXE(USART6)); LL_USART_TransmitData8(USART6, data); } for (i = 0; i < len; i++) SendByte(data[i]); while (!LL_USART_IsActiveFlag_TC(USART6));

等 TXE 的时候，CPU 停在 while 里。启动时打印一行字可以用这种写法。数据包不走这里，数据包用两个槽交给 DMA 发送。

5. 上一字节还没读走，下一字节又到了

DR 只有一个字节的位置。不用 DMA 时，CPU 必须在下一个字节到来之前把 DR 读走。没读走就再来一个字节，硬件放不下两个，前一个字节丢掉，同时把 ORE 置 1。ORE 就是 Overrun，意思是来不及读。

这个标志不会自己灭。按这颗芯片的要求，先读 SR，再读 DR，标志才清除。

关中断太久，CPU 就来不及进接收中断，ORE 就会出现。当前工程不用 CPU 一个字节读一次 DR。DMA 收到请求后把 DR 里的字节拷进内存，正常接收不靠这里。
