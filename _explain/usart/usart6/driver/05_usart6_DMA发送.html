3. 初始化一次，发送时重复启动

USART6_LL_TxDmaInit()在 USART6_LL_Init() 中执行一次。它打开 DMA2 时钟，选择 Stream6 Channel5，方向设为内存到外设，外设地址固定为 USART6->DR，内存地址递增，数据宽度为字节，模式为普通模式，并打开 TC、TE、DME 中断。

普通模式发完一帧后 EN 自动清零。下一帧长度和数组地址都可能不同，所以每次 USART6_LL_SendDma() 重新执行：

USART6_LL_TxDmaClearFlags(); LL_DMA_SetMemoryAddress(DMA2, LL_DMA_STREAM_6, (uint32_t)data); LL_DMA_SetDataLength(DMA2, LL_DMA_STREAM_6, len); LL_DMA_EnableStream(DMA2, LL_DMA_STREAM_6);

EnableStream()后 DMA 硬件开始工作，CPU 继续执行后面的超时计算。任务执行到 ulTaskNotifyTake() 时才进入阻塞；这时 DMA 仍在发送。若 DMA 在任务到达等待语句前已经完成，中断先把通知计数加1，等待语句发现计数存在后立即返回。

4. 临界区与 busy

临界区包住“检查 busy、写 busy、设置地址和长度、启动 Stream”这一段。两个任务不能同时看到 busy == 0 并同时改 Stream6。

退出临界区时本次配置已经写完，busy已经是1。其他任务可以运行，但再次调用 SendDma() 会因 busy == 1 返回0，不能改本次地址和 NDTR。printf也会先等 busy 清零，避免它的字节插入 DMA 数据中间。

TX中断优先级为5，临界区内它暂时不能运行。配置完成后必须退出临界区，完成中断才能调用 FreeRTOS 的 FromISR 接口。

5. 通知的发送与接收

任务接收

第161行 ulTaskNotifyTake(pdTRUE, 0) 清除上一笔残留计数，等待时间为0，不阻塞。

第191行 ulTaskNotifyTake(pdTRUE, timeout_ticks) 读取本次计数；计数为0时任务进入 Blocked。

中断发送

DMA2_Stream6_IRQHandler()调用 USART6_LL_DmaTxIRQHandler()。

TC时 result = 1；TE或DME时 result = -1。随后 vTaskNotifyGiveFromISR(wait_task) 把该任务的通知计数加1。

xTaskGetCurrentTaskHandle()返回的是正在执行 SendDma() 的任务。当前调用链来自 USART6_AppTask()，所以保存下来的就是这个任务。

6. 超时时间

115200、8N1每个字节占10位。代码先把线路时间向上取整为毫秒，再加10ms余量：

timeout_ms = (len * 10 * 1000 + 115199) / 115200; timeout_ms += 10;

6字节约0.52ms，向上取整为1ms，加余量后等待11ms。68字节最长帧约5.9ms，加余量后等待16ms。1ms一个FreeRTOS节拍，所以等待节拍数与毫秒数相同。

ulTaskNotifyTake()返回0表示等待时间内没有收到通知。任务从这一行继续执行，先停止 Stream6、调用 USART6_LL_TxDmaClearFlags()、清除等待任务和 busy，然后本次发送返回0。它不会从任务函数开头重新运行。

7. 两种完成标志

标志置位含义当前处理
DMA TC最后一个字节已经写入 USART6->DRStream6中断记录成功并发出任务通知
USART TC移位寄存器空，最后一个停止位已从PC6发出任务醒来后轮询该标志，然后清除 busy
TXEDR为空，可以接收下一个字节USART硬件自动置1；DMA或CPU写入DR后硬件清零

TXE循环由硬件控制：DR空时TXE为1，USART向DMA发出请求；DMA写入一字节后TXE清零；该字节进入移位寄存器后TXE再次为1。

8. 标志清理函数

USART6_LL_TxDmaClearFlags()统一清除 Stream6 的 TC、TE、DME、FE。TX未使用半传输，所以函数不处理 HT。四个调用点的目的不同：

  1. 初始化时清除上电残留状态。
  2. 每次启动前清除上一笔残留，避免旧TC让新传输立即被当成完成。
  3. 完成中断里应答本次事件，避免中断返回后立刻再次进入。
  4. 超时停止 Stream 后清除本次残留，让下一次发送从干净状态开始。

9. 发送缓冲区是临时变量

frame[68]是 USART6_Packet_Send() 的临时数组，没有单独的发送队列。DMA 直接读它，所以函数必须等到发送结束再返回。以后如果调用方要马上返回，再改成持久缓冲区。
