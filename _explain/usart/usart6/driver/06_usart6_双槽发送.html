USART6 教程 6：两个发送槽

按源码把一次发送走完：USART6_Packet_Send() 组帧，USART6_LL_TxAlloc() 领槽，USART6_LL_TxCommit() 提交，USART6_LL_TxKick() 打开 DMA，完成中断再换下一个槽。

协议字节由 USART6_Packet_Send() 写入槽的 data[]。usart6_ll.c 只按地址和长度把这块内存交给 DMA2 Stream6。回显任务在 USART6_Packet_Read() 取出一帧 DATA 之后，调用 USART6_Packet_Send(payload, length)。

槽是静态数组 usart6_tx_slot[2]。每个元素里有 data[68]、len 和 state。68 是这一槽最多能装的字节数，DMA 实际搬走的个数是提交时写下的 len。

2. Packet_Send：把 Hi 写成 6 个字节

调用 USART6_Packet_Send("Hi", 2) 时，函数先看参数。载荷指针是空并且长度不是 0，或者长度大于 64，函数直接返回，不领槽。

frame = USART6_LL_TxAlloc(&slot_id); if(frame == 0) return;

frame 指向领到的那一槽的 data[0]。slot_id 被写成 0 或 1。返回 0 表示这次没有槽，后面的写入和提交都不执行。

frame_pos 从 0 开始。后置加加先写入当前下标，再把下标加 1。载荷 48 69 走完时，槽里是：

执行的语句写入写完后的 frame_pos
frame[frame_pos++] = 0xAAdata[0] = AA1
frame[frame_pos++] = 0x55data[1] = 552
frame[frame_pos++] = 2data[2] = 023
frame[frame_pos++] = payload[0]data[3] = 48，同时 value = 02 ^ 484
frame[frame_pos++] = payload[1]data[4] = 69，同时 value = 02 ^ 48 ^ 69 = 235
frame[frame_pos++] = valuedata[5] = 236

循环用 payload[index] 填 DATA，并用同一个 value 做异或。value 的初值是长度字节 02，所以校验盖住的是 LEN 和 DATA，不包括 AA 55。

USART6_LL_TxCommit(slot_id, frame_pos);

这里的 frame_pos 已经是 6。提交的长度是整帧字节数，包括包头和校验。空包 AA 55 00 00 提交的长度是 4。最长 DATA 为 64 时，提交的长度是 68。

回显区里连续出现的 AA 55 02 48 69 23，是这个函数被调用了很多次。每一次 USART6_Packet_Read() 只取走队列里的 6 个字节，把 DATA 长度 2 交给任务，任务再调用一次 USART6_Packet_Send()。64 限制的是这一次参数 len，也就是 DATA 的字节数。

3. TxAlloc：决定这次用哪一个槽

函数开头有三道关，任何一道失败都返回 NULL，槽的状态和下标都不变。

  1. slot_id == NULL 或信号量句柄还是 NULL。这里的 NULL 表示没有传入槽号的地址，或者 USART6_LL_TxFreeInit() 还没创建信号量。
  2. 调度器还没运行。启动打印发生在 vTaskStartScheduler() 之前，不能在这里领槽。
  3. xSemaphoreTake(usart6_tx_free, portMAX_DELAY) 没有返回 pdTRUE。

信号量创建时计数是 2。前两次 Take 把计数减到 1、再减到 0，函数继续往下走。第三次 Take 时计数已经是 0，这个任务停在 Take 里面，直到完成中断执行 xSemaphoreGiveFromISR()。停住的是这一个任务，调度器可以去运行别的任务。正常醒来时 Take 返回 pdTRUE，不会走到 return NULL。

通过 Take 之后进入临界区：

id = usart6_tx_wr; if(usart6_tx_slot[id].state != USART6_TX_EMPTY){ taskEXIT_CRITICAL(); xSemaphoreGive(usart6_tx_free); return NULL; } usart6_tx_slot[id].state = USART6_TX_FILL; usart6_tx_slot[id].len = 0U; usart6_tx_wr = (usart6_tx_wr + 1U) % 2; taskEXIT_CRITICAL(); *slot_id = id; return usart6_tx_slot[id].data;

id = usart6_tx_wr 记下这次要领的槽号。上电后 wr 是 0，第一次领到槽 0。状态若已经不是 EMPTY，先退出临界区，再把刚才减掉的信号量加回去，返回 NULL。wr 保持不动。

状态是 EMPTY 时，改成 FILL，长度先写成 0。DMA 看到 FILL 不会读这块内存。然后 wr 加 1 再对 2 取余：0 变成 1，1 变成 0。这是下一次领取要用的槽号。临界区结束后，把槽号写到调用者的 slot_id，返回 data 的地址。此时字节还没写，写入发生在回到 USART6_Packet_Send() 之后。

4. TxCommit：长度写入之后才允许 DMA 来取

if((slot_id >= 2) || (len == 0) || (len > 68)) return; taskENTER_CRITICAL(); if(usart6_tx_slot[slot_id].state != USART6_TX_FILL){ taskEXIT_CRITICAL(); return; } usart6_tx_slot[slot_id].len = len; usart6_tx_slot[slot_id].state = USART6_TX_READY; USART6_LL_TxKick(); taskEXIT_CRITICAL();

槽号越界、长度为 0 或长度大于 68，函数在进临界区之前返回。当前 USART6_Packet_Send() 传来的 frame_pos 是 4 到 68，这三句判断都不会成立。

进临界区后，槽必须正处在 FILL。不是 FILL 就退出临界区并返回，信号量计数不加。是 FILL 时，先把实际字节数写进 len，再把状态改成 READY，然后调用 USART6_LL_TxKick()。调用 TxKick() 时，临界区还没退出。

5. TxKick：只有 rd 那一槽就绪才开 Stream6

初始化时 USART6_LL_TxDmaInit() 已经把 Stream6 配成内存到外设、普通模式、Channel5，外设地址固定是 USART6->DR。每次真正发送前，TxKick() 再改这一次的内存地址和 NDTR。

if(usart6_tx_dma_busy != 0U) return; if(usart6_tx_slot[usart6_tx_rd].state != USART6_TX_READY) return;

这两句返回时，TxCommit() 已经把本次槽号的状态改成了 READY，长度也在。返回只表示现在不能开 DMA。第一句是因为 Stream6 正在读另一个槽。第二句看的是 rd，不一定是刚提交的那个槽号。例如刚把槽 1 改成 READY，而 rd 还停在槽 0，槽 0 仍是 FILL，函数就从第二句返回。槽 1 的 6 个字节留在 data[] 里。

两句都不成立时，按这个顺序启动：

  1. slot[rd] 改为 SEND，usart6_tx_dma_busy = 1，usart6_tx_need_tc = 0。新的一帧已经开始，printf 不必再为上一帧等停止位。
  2. 关闭 Stream6，并等到 EN 硬件位变成 0。普通模式在上次传完时硬件会清 EN，这里仍先确认停止，再改地址和长度。
  3. 清掉 TC、TE、DME、FE。发送没有开半传输中断，所以不清 HT。
  4. 内存地址设为 slot[rd].data，NDTR 设为 slot[rd].len。Hi 这一帧的 NDTR 是 6。
  5. 打开 Stream6。DMA 按字节把 data[] 写入 USART6->DR，USART 从 PC6 移位送出。

6. 完成中断：释放当前槽，再看下一槽

DMA2_Stream6_IRQHandler() 进入 USART6_LL_DmaTxIRQHandler()。这条中断优先级是 5，可以调用 xSemaphoreGiveFromISR()。

has_event = TE 或 DME 或 TC 有一个成立; USART6_LL_TxDmaClearFlags(); if(has_event == 0) return;

标志先清掉。三个事件都没有，函数返回，不改槽，也不 Give。TE、DME 和 TC 走同一段后续代码，出错的帧不重发。

saved = taskENTER_CRITICAL_FROM_ISR(); if(usart6_tx_slot[usart6_tx_rd].state != USART6_TX_SEND){ taskEXIT_CRITICAL_FROM_ISR(saved); return; } usart6_tx_slot[usart6_tx_rd].state = USART6_TX_EMPTY; usart6_tx_slot[usart6_tx_rd].len = 0; usart6_tx_rd = (usart6_tx_rd + 1) % 2; usart6_tx_dma_busy = 0; if(usart6_tx_slot[usart6_tx_rd].state == USART6_TX_READY) USART6_LL_TxKick(); else usart6_tx_need_tc = 1; taskEXIT_CRITICAL_FROM_ISR(saved);

rd 指向的槽必须是 SEND。不是 SEND 就退出临界区并返回，信号量不加。这避免一次多余的中断把空槽再释放一遍。

是 SEND 时，这个槽改回 EMPTY，长度清 0，rd 前进一格，busy 先清 0。接着看新的 rd：

  • 新槽已是 READY：立刻再调用 TxKick()。它把新槽改成 SEND，并把 busy 设回 1。两个槽就这样接上，中间不用等任务再提交一次。
  • 新槽不是 READY：没有下一帧可发，need_tc 设为 1。DMA 的 TC 只说明内存里的字节已经写入 DR，最后一个字节的停止位可能还在 PC6 上移出。printf 随后写 DR 之前要先看到 USART 的 TC。
xSemaphoreGiveFromISR(usart6_tx_free, &higher_priority_task_woken); portYIELD_FROM_ISR(higher_priority_task_woken);

Give 加的是刚释放的那一个槽。正在被 TxKick() 接上的下一槽，计数早在它领取时减过，这里不再减。若有任务停在 Take 上，并且它的优先级更高，portYIELD_FROM_ISR() 让它尽快继续领槽。

7. 两个任务按函数走一遍

开始时两个槽都是 EMPTY，wr = 0，rd = 0，busy = 0，信号量计数是 2。任务 A、任务 B 各发一帧，A 先领槽但后写完。

B 提交之后到 A 提交之前，槽 1 的字节已经在 data[] 里，只是 rd 还没轮到它。第三个任务若在信号量为 0 时调用 USART6_Packet_Send()，会停在 TxAlloc() 的 Take 上。槽 0 的完成中断把计数加到 1 之后，它才能领走此时已经是 EMPTY 的槽 0。

8. SendByte：在两帧 DMA 之间写入一个字节

printf 每个字符调用一次 fputc()，fputc() 再调用 USART6_LL_SendByte()。一次调用只处理参数里的那一个字节。

调度器未运行时，函数等到 TXE 置位，把字节写入 DR，然后返回。这一段不看槽，也不看 busy。

调度器运行后进入 for(;;)：

  1. while(usart6_tx_dma_busy != 0) 空等。DMA 正在搬某一槽时，这个字节不能写进 DR，否则会插进那一帧中间。busy 为 1 就等，另一个槽是空的也等。这里是空等，任务不会像 Take 那样睡下去。
  2. need_tc 为 1 时，再空等到 USART 的 TC。这是上一小节最后一帧结束时留下的标志，用来等最后一个停止位离开 PC6。
  3. 进入临界区，再读一次 busy。等 TC 的时候，别的任务可能已经 TxCommit() 并且把 busy 设成了 1。
  4. busy 仍是 0：清掉 need_tc，等到 TXE，把本次的这一个字节写入 DR，退出临界区，return。这个字符发送结束。
  5. busy 已经是 1：退出临界区。函数末尾的循环括号回到第 1 步，继续等 DMA。源码里没有写 continue，回到循环开头靠的是 for(;;) 自己的结尾。

一个字符从 SendByte() 返回后，调度器可以切到另一个任务。那个任务能够把一整帧领槽、写完、提交。所以一串 printf 的两个字符之间，线上可以先出去一整帧 AA 55 ...。临界区只包住一次读 busy、等 TXE 和写 DR。

USART6_LL_Send() 对数组里的每个字节调用一次 SendByte()，全部返回后再等一次 USART TC。启动信息使用这个函数。

完成中断负责把 busy 清 0。调用 SendByte() 的代码若停在把优先级 5 挡住的临界区里，或者直接停在 Stream6 的中断函数里，完成中断进不来，while(busy) 就一直等下去。
