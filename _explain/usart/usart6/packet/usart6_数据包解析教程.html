两个接收缓冲区的职责：DMA缓冲区保存硬件刚搬入的字节；中断中的 USART6_LL_RxDmaDrain() 把新增字节复制到软件环形队列；数据包解析器从软件环形队列读取候选帧。

UART硬件输出连续的原始字节流；软件协议层根据包头、LEN和XOR确定每个数据包的边界与有效性。

2. 三个文件，三个清晰边界

usart6_ll.c

负责GPIO、USART6、DMA、中断、两个接收缓冲区以及原始字节接口。

不知道 AA 55、LEN、XOR。

usart6_packet.c

借助 Count、Peek、Drop 从软件队列检查协议并组包发送。

不直接配置 USART和DMA。

usart6_app.c

FreeRTOS任务反复调用 USART6_Packet_Read()；读到合法包后调用 USART6_Packet_Send() 原样回发。

分层把三个变化原因隔开：换芯片外设主要改LL；换协议主要改Packet；换业务行为主要改App。

3. 变量的含义、修改者与变化规则

3.1 底层接收变量

变量含义谁修改如何变化
usart6_dma_rx_buf[256]DMA硬件循环写入的临时数组DMA2硬件从下标0写到255，随后回绕到0继续写；数组值一直保留，直到DMA下一轮写入时覆盖
usart6_dma_rx_pos软件下一次应从DMA数组读取的下标RxDmaDrain()；初始化或错误重启时置0每复制一个字节就加1，再与255按位与，所以255之后变0
NDTRDMA本轮还要搬运多少个字节DMA硬件递减；初始化/重启时装入256256→255→…→1→0；循环模式随后自动重新装载为256
dma_pos由NDTR换算出的“DMA下一次写入下标”快照RxDmaDrain()每次调用重新计算(256 - NDTR) & 255，范围0～255
usart6_rx_buf[256]供协议层查看和消费的软件环形队列中断通过 RxPush() 写入写满后回绕；为了区分空和满，始终空出一格，最多存255字节
usart6_rx_head软件队列下一次写入位置RxPush()成功写入后加1并回绕；队列满时不动
usart6_rx_tail软件队列第一个未处理字节的位置RxDrop()或ReadByte()消费多少字节就前进多少，再回绕

3.2 数据包解析变量

变量当前一次调用中的用途
available软件队列当前尚未处理的字节总数，由 USART6_LL_RxCount() 得到
data_len当前候选帧里的LEN字段，只表示DATA长度，合法范围0～64
frame_len候选完整帧总长度：2字节包头 + 1字节LEN + DATA + 1字节XOR
index复制DATA时的循环下标
now检查半包超时时读取的当前毫秒计数
usart6_packet_wait是否已经因为当前队头的半包开始等待
usart6_packet_t0开始等待当前半包时的毫秒时间

4. DMA循环接收与新增字节定位

4.1 DMA接收初始化配置

  1. 打开DMA2时钟，停止Stream1，并等待硬件确认EN清零。
  2. 选择固定映射 DMA2 Stream1 Channel5，方向设为外设到内存。
  3. 外设地址固定为 USART6->DR；内存地址从 usart6_dma_rx_buf[0] 开始并自动递增。
  4. 两端数据宽度均为BYTE；使用循环模式；关闭FIFO，采用直接模式。
  5. 给NDTR装入256，开启HT、TC、TE、DME中断，最后启动Stream。

4.2 NDTR：当前一轮的剩余传输次数

NDTR由DMA硬件维护，表示当前这一轮还要完成多少次传输。本工程一次传输一个字节，所以NDTR从256开始，每搬入一个字节减1；减到0后，循环模式将它重新装载为256。NDTR描述DMA传输进度，与数组单元中保留的新旧数值无关。

刚启动

NDTR = 256

dma_pos = (256 - 256) & 255 = 0

意思是这一轮尚未搬运，DMA下一次写 usart6_dma_rx_buf[0]。

收到3字节

NDTR = 253

dma_pos = 3

下标0、1、2已被DMA写入；DMA下一次写下标3。

4.3 RxDmaDrain()的两个位置

dma_pos = (256 - NDTR) & 255; while (usart6_dma_rx_pos != dma_pos) { 把 dma数组[usart6_dma_rx_pos] 追加到软件队列; usart6_dma_rx_pos = (usart6_dma_rx_pos + 1) & 255; }

dma_pos是本次查看硬件得到的终点；usart6_dma_rx_pos是软件上次已经复制到哪里。两者之间的区间就是“DMA已写、软件尚未复制”的新增字节。

例：软件上次已处理到下标7，所以 usart6_dma_rx_pos=7；后来DMA又写到下标10，所以 dma_pos=10。循环复制下标7、8、9，完成后软件位置变为10。下标0～6中的值已经处理过，软件读位置保证下一次从下标10继续。

4.4 DMA回绕时的读取顺序

假设软件位置为254，DMA写完下标254、255后回到0，又写了0、1、2，此时 dma_pos=3。循环依次读取254、255、0、1、2；每次执行 (位置 + 1) & 255，255的下一个位置自然变为0，最后追到3停止。

位置关系按照环形前进方向判断。回绕前，软件位置通常小于或等于DMA位置；回绕后，软件位置的数值可以大于DMA位置，循环仍从软件位置开始，经过255和0，最后追到DMA位置。

4.5 HT、TC、IDLE的触发时机与作用

事件触发时机Drain的作用
HT（半传输）DMA本轮写完前128字节及时把前半区复制走，避免等满256字节才处理
TC（传输完成）DMA本轮写完后128字节并准备回绕提交后半区；循环模式随后从数组0继续写
IDLE（线路空闲）接收完最后一个字节后，持续约一个字符时间没有新字节短包可能永远到不了128字节，IDLE负责及时提交这些新增字节

5. 软件环形队列的查看与消费接口

DMA区域会被硬件不断覆盖，不适合让较慢的任务直接保留一个候选帧。中断先把新增字节放进软件队列，任务可以按自己的速度检查。

5.1 head和tail的推进规则

next = (head + 1) & 255; if (next == tail) 队列已满，丢弃这个新字节; 否则： usart6_rx_buf[head] = 新字节; head = next; 消费 n 字节时： tail = (tail + n) & 255;

& 255叫“与上掩码”。256是2的幂，下标的低8位正好表示0～255。256的二进制最低9位为 1 0000 0000，与 255（0 1111 1111） 按位与后变成0，效果等同于对256取模。

5.2 Count、Peek、Drop与ReadByte的职责

RxCount()

先问“现在有几个字节”，避免越界查看，也能判断完整帧是否到齐。

RxPeek(offset)

查看指定偏移处的字节并保持tail不变，使解析器能够先验证包头、LEN和XOR。

RxDrop(n)

确认应消费或应丢弃后，再一次移动tail。合法帧丢整帧；错误候选只滑动1字节。

USART6_LL_ReadByte()执行“读取一个字节并立即推进tail”，适合逐字节业务。它与数据包解析器共用同一个tail，因此本工程选择由数据包解析器统一消费队列。

两个Drop的职责：USART6_LL_RxDrop()负责移动底层tail；USART6_Packet_Drop()在调用底层Drop后，同时清除与原队头绑定的半包等待状态。协议层使用 USART6_Packet_Drop()。

6. 协议格式和 USART6_Packet_Read() 完整流程

AA包头0
55包头1
LENDATA字节数
DATA…0～64字节
XORLEN ^ DATA…

XOR不包含AA和55。空DATA帧也合法：LEN为0，XOR也为0，总帧长4字节。

6.1 每次调用Read时按这个顺序检查

  1. 参数 payload 或 len 为空，无法交付结果，直接返回0。
  2. 读取 available。不足2字节时连完整包头都无法判断，保留已有字节并返回0。
  3. 队头值≠AA：当前字节无法构成协议包头，丢1字节并在本次调用中继续检查。
  4. 第一个字节为AA、第二个字节≠55：只丢第一个AA，因为第二个字节本身可能是下一帧的AA。
  5. AA 55正确但LEN还没到：保留当前候选并返回0。
  6. 读出 data_len。若大于64，当前候选帧判定无效，只滑动1字节后重新找包头。
  7. 计算 frame_len = 3 + data_len + 1。字节尚未到齐时进入半包等待。
  8. 首次遇到这个半包时记录 usart6_packet_t0；后续调用若等待达到20ms，滑动1字节，避免错误LEN让队列永久堵住。
  9. 完整帧到齐后，用 USART6_Packet_CalcXor() 计算LEN与全部DATA的异或值，并与帧尾比较。
  10. XOR不一致，只滑动1字节继续重新同步；一致则复制DATA、写回长度、Drop整个帧并返回1。
一次调用中的连续扫描：for(;;)配合continue，在一次Read调用里反复丢弃明确无效的队头字节或候选帧起点，直到找到一帧，或者现有字节不足而返回等待。协议层使用“无效字节”这个名称；USART硬件的NE表示线路采样噪声错误。

7. 用真实字节推演解析过程

7.1 正常帧

AA5502486923

frame_len = 3 + 2 + 1 = 6。计算 02 ^ 48 ^ 69 = 23，与帧尾一致。DATA 48 69 被复制给任务，然后tail前进6格。

7.2 前面有无效字节和重复AA

00AAAA88AA55…
  1. 队头00≠AA，Drop 1，tail指向第一个AA。
  2. 第一个AA后的字节为AA，与55不相等，只丢前一个AA；后一个AA保留为新的候选。
  3. 新的AA后面是88，仍只丢这个AA。
  4. 88≠AA，Drop 1。
  5. 现在队头是AA 55，开始检查LEN、完整性和XOR。

7.3 非法LEN后的单字节滑动

非法LEN只能证明“以当前第一个AA为起点”的候选帧无效。后面的55、LEN字段或DATA位置仍可能包含下一帧的AA。解析器因此从当前候选起点向前滑动1字节，再重新扫描，使每个可能的包头位置都有机会被检查。

7.4 半包和粘包

半包

队列里只有 AA 55 02 48，完整帧应有6字节。解析器不移动tail，返回0。以后任务再次调用时继续检查；达到20ms仍不完整才滑动1字节。

粘包

两个完整帧连续进入队列。第一次Read只Drop第一帧并返回1；第二帧仍在tail之后，下次任务循环再取出。

8. USART6_Packet_Send() 的组帧流程

发送函数先在局部数组 frame[68] 中构造完整协议帧，再把整帧交给底层发送。68来自2字节包头 + 1字节LEN + 最多64字节DATA + 1字节XOR。

  1. 检查参数：DATA长度为0～64；长度大于0时payload需要指向有效数据区。
  2. frame_pos从0开始，依次写入AA、55、LEN；每写一个字节就自增，始终指向下一个可写位置。
  3. value以LEN为初值；复制每个DATA到frame时，同时执行 value ^= payload[index]。
  4. 把最终XOR写在帧尾，然后调用 USART6_LL_Send(frame, frame_pos)。
  5. 底层采用TXE/TC轮询发送：等待TXE后逐字节写DR，最后等待TC确保停止位发送完成。当前发送路径未使用DMA。

9. 中断处理、错误含义和当前边界

9.1 两个硬件中断入口的职责

入口检查的事件处理动作
DMA2_Stream1_IRQHandler()HT、TC、TE、DME转到 USART6_LL_DmaRxIRQHandler()。HT/TC清标志后Drain；TE/DME先尽量Drain已完成数据，再重启DMA。
USART6_IRQHandler()IDLE、ORE、FE、NE转到 USART6_LL_IRQHandler()。按STM32F4要求先读SR再读DR清标志，然后Drain。

9.2 DMA与USART错误事件的含义

TE：DMA Transfer Error，DMA传输错误。

DME：DMA Direct Mode Error，DMA关闭FIFO、使用直接模式时的错误。

FE（DMA）：FIFO Error。本工程关闭FIFO，但初始化和中断中仍清除可能残留的标志。

ORE：USART Overrun Error，前一个字节未及时转走，新字节又到达。

FE（USART）：Framing Error，停止位等帧格式异常。

NE：USART Noise Error，硬件采样检测到线路噪声。协议层的“无效字节”表示字节值不符合数据包格式，两者分别属于硬件层和协议层。

当前实现的可观察信息：中断负责清标志、保存可用数据和恢复接收。代码未保存错误次数、发生时间和事件日志，因此运行结束后没有可供查询的历史错误记录。ISR的工作范围也不包含数据包解析、发送、printf和FreeRTOS API调用。

9.3 IDLE读DR与DMA的竞态边界

STM32F4清IDLE/ORE/FE/NE要求顺序读取SR和DR。与此同时RX接收由DMA负责，读取DR的动作与DMA请求可能靠得很近。当前实现先读SR、再读DR清标志，然后依据NDTR执行Drain，这是当前代码采用的处理顺序。

当前实现采用一次NDTR快照，适合当前实验和教学。持续满线速、高可靠场景可进一步加入短暂关闭DMA、稳定读取NDTR两次等竞态处理，并结合芯片参考手册、总线时序和压力测试完成验证。

10. FreeRTOS任务的消费过程与队列满处理

USART6_AppTask()负责消费合法数据包。每轮调用Read：成功就回发；失败就延时1个tick，避免空转占满CPU。

for (;;) { if (USART6_Packet_Read(payload, &length)) { USART6_Packet_Send(payload, length); } else { vTaskDelay(1U); } }

任务通过Read推进tail并释放软件队列空间。任务停止调用Read时，DMA和中断仍继续接收，head继续前进而tail保持原位；队列达到255字节后，RxPush()丢弃后来到的新字节。完整的数据处理链必须同时包含硬件接收和任务消费。

这里的软件队列是单生产者/单消费者结构：生产动作只在USART6相关中断上下文中发生，消费动作只在这个任务中发生。若未来增加第二个任务也读取tail，或多个执行上下文同时写head，就不再满足该前提，需要锁、临界区或改用FreeRTOS队列/StreamBuffer。

13. 不背代码，记住约束

  1. DMA负责持续搬运；dma_pos记录硬件写入终点，usart6_dma_rx_pos记录软件下一读取位置。
  2. DMA区域会回绕覆盖，所以中断要通过HT、TC、IDLE及时Drain到软件队列。
  3. 协议判断可能失败，所以必须先Peek验证，最后才Drop消费。
  4. 无效候选采用单字节滑动，使后续每个字节都有机会成为新包头。
  5. 半包记录等待起点并设置20ms超时，使错误候选能够被释放。
  6. ISR负责字节搬运和硬件恢复；任务负责解析、发送与业务行为。
记忆主线是“问题 → 约束 → 接口”：硬件连续流需要分帧；Peek在保持tail不变的情况下完成验证；Drop在验证后推进tail；缓冲区回绕要求所有位置按环形规则推进。函数名和局部变量可随时查源码，重点是理解每个接口解决的约束。
